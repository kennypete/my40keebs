= My 40&#x0025; keyboards

I have several 40&#x0025; Planck-style keyboards with my preferred MIT layout.
For a long time, my favourite was the (now discontinued) Planck&#x00A0;Ez.  It
was my first 40&#x0025; keyboard and, aside from once having to solder a broken
connection, is still going strong.

// Blank line is needed in Codeberg
ifdef::env-codeberg[&#x00A0; ]

Over time, I bought and used other 40%s.  The only one I am no longer using is
a Contra, which was my only foray into soldering a full board, which was not
really for me.  It was good, until it died &#x2013; although I couldn’t be
bothered with heaps of soldering it taught me a lot.  It also confirmed I
dislike the Grid layout, never using the (3,5) key, so all my 40&#x0025;
keyboards are MIT layout now (i.e., with a 2U spacebar).

ifdef::env-codeberg[&#x00A0; ]

In 2026, I bought a Chosfox Geonix Rev.2.5 and love its hardware and features.
The combination of wireless (Bluetooth _and_ 2.4G enabled), Planck MIT, and low
profile Kailh Choc V2 Deep sea silent tactile switches is near to perfect, IMO.

ifdef::env-codeberg[&#x00A0; ]

What acquiring the Geonix sparked was going back to my other keyboards, which
had been set up in an only mostly-the-same layout, functionality, and so forth.
For example, one of my KPRepublic BM40 keyboards, which I use in the office,
did not have backlighting working (for a reason I cannot recall now).  Also, I
had never looked into per-key RGB, which was one of the things I rate with the
Planck Ez, where it is controlled with ZSA’s Oryx configurator.

[#behaviourandfeaturesstandardisation]
== Behaviours, features, and per-key RGB backlight standardisation

I set off on a quest to create an almost identical setup across my current
keyboards, which, in order of acquisition were:

What was interesting was the number of redundant features and other things
(inherently inert on some boards, stuff I do not use, and so forth) in the
BM40, CSTC40, and Geonix QMK-Vial setups.  In a way that’s unsurprising.  Lots
of things are often not looked at in detail, or at all, by developers or users.
I certainly hadn’t.

ifdef::env-codeberg[&#x00A0; ]

Typically, I was content with launching Vial, setting the keymaps on a few
layers to what I was used to, and moving on.  And that is fine to a point.  I
found the core things like my base layer and most of the Lower and Raise layers
I had no issue with, but the less used stuff was too haphazard, with slight
differences, etc.  On reflection now, the convergence work here was a “rabbit
hole”, though it was worthwhile because now any new board I acquire will have a
much easier path to alignment with my preferences and congruity with my other
40&#x0025; boards.

ifdef::env-codeberg[&#x00A0; ]
